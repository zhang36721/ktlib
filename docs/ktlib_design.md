# ktlib 架构设计文档

## 1. 整体架构概览

ktlib 采用分层架构设计，从下到上分为四个层次：

```
┌─────────────────────────────────────────┐
│          应用层（用户代码）               │
├─────────────────────────────────────────┤
│     kt_drivers - 应用层驱动              │
│  (LED, Button, Buzzer, UART Protocol)   │
├─────────────────────────────────────────┤
│     kt_components - 通用组件             │
│   (Ring Buffer, Soft Timer, CRC)        │
├─────────────────────────────────────────┤
│     kt_port - 平台适配层                 │
│  (GPIO, UART, Time - 按平台实现)         │
├─────────────────────────────────────────┤
│     kt_core - 核心基础                   │
│  (Types, Config, Error, Debug, Utils)   │
├─────────────────────────────────────────┤
│           硬件抽象层（MCU）               │
│    (STM32 HAL / ESP32 / 8051 / Mock)    │
└─────────────────────────────────────────┘
```

## 2. 各层详细说明

### 2.1 kt_core - 核心基础层

**职责**：提供整个库的基础支撑，不依赖任何特定硬件。

**包含模块**：

| 文件 | 说明 |
|------|------|
| `kt_types.h` | 统一的数据类型定义（如 kt_int8_t, kt_uint8_t, kt_bool_t 等） |
| `kt_config.h` | 可配置的宏定义（如调试开关、缓冲区大小等） |
| `kt_error.h` | 统一的错误码系统（如 KT_OK, KT_ERROR 等） |
| `kt_debug.h` | 调试打印和断言宏（如 KT_DEBUG, KT_ASSERT 等） |
| `kt_utils.h` | 常用工具函数声明（如位操作、数组操作等） |

**设计原则**：
- 零依赖：不依赖任何外部库或硬件
- 可配置：通过宏定义控制功能开关
- 类型安全：使用统一的前缀命名避免冲突

### 2.2 kt_port - 平台适配层

**职责**：隔离不同MCU平台的硬件差异，提供统一的硬件操作接口。

**接口分类**：

| 接口类别 | 函数示例 | 说明 |
|----------|----------|------|
| GPIO | `kt_port_gpio_init()` | GPIO初始化 |
| | `kt_port_gpio_write()` | GPIO写操作 |
| | `kt_port_gpio_read()` | GPIO读操作 |
| UART | `kt_port_uart_init()` | UART初始化 |
| | `kt_port_uart_send()` | UART发送数据 |
| | `kt_port_uart_receive()` | UART接收数据 |
| Time | `kt_port_delay_ms()` | 毫秒级延时 |
| | `kt_port_get_tick()` | 获取系统时钟节拍 |

**平台实现**：

| 平台 | 目录 | 说明 |
|------|------|------|
| STM32 HAL | `stm32_hal/` | 基于STM32 HAL库实现 |
| ESP32 | `esp32/` | 基于ESP-IDF实现 |
| 8051 | `8051/` | 基于8051单片机实现 |
| Mock | `mock/` | 模拟实现，用于PC端测试 |

**设计原则**：
- 接口统一：所有平台提供相同的函数签名
- 弱耦合：上层代码只调用接口，不关心具体实现
- 可替换：通过条件编译选择不同的平台实现

### 2.3 kt_components - 通用组件层

**职责**：提供可复用的软件组件，这些组件与具体硬件无关。

**包含组件**：

| 组件 | 文件 | 说明 |
|------|------|------|
| 环形缓冲区 | `kt_ringbuf.h/.c` | 用于数据缓存，常用于UART收发 |
| 软件定时器 | `kt_soft_timer.h/.c` | 提供定时功能，支持多个定时器 |
| CRC校验 | `kt_crc.h/.c` | 数据完整性校验 |

**设计原则**：
- 独立性：组件之间相互独立，可单独使用
- 通用性：适用于多种应用场景
- 高效性：资源占用少，执行效率高

### 2.4 kt_drivers - 应用层驱动层

**职责**：提供面向应用的驱动程序，直接服务于用户代码。

**包含驱动**：

| 驱动 | 目录 | 说明 |
|------|------|------|
| LED驱动 | `led/` | 支持闪烁、呼吸等效果 |
| 按键驱动 | `button/` | 支持单击、双击、长按等事件 |
| 蜂鸣器驱动 | `buzzer/` | 支持不同音调和节奏 |
| UART协议 | `uart_protocol/` | 简单的通信协议框架 |

**设计原则**：
- 易用性：提供简洁的API接口
- 可配置：支持多种配置选项
- 健壮性：完善的错误处理

## 3. 数据流示例

以按键驱动为例，展示数据在各层之间的流动：

```
硬件层：GPIO引脚电平变化
    ↓
kt_port: kt_port_gpio_read() 读取GPIO状态
    ↓
kt_drivers/button: kt_button_scan() 扫描按键状态
    ↓
kt_components/soft_timer: 处理长按计时
    ↓
应用层：获取按键事件（单击、双击、长按）
```

## 4. 移植流程

1. **选择平台**：根据你的MCU选择对应的 `kt_port` 实现
2. **配置功能**：在 `kt_config.h` 中启用/禁用所需功能
3. **实现适配**：如果没有对应平台实现，需要自己实现 `kt_port` 接口
4. **调用驱动**：使用 `kt_drivers` 中的驱动程序

## 5. 命名规范

所有公共符号使用 `kt_` 或 `KT_` 前缀：

- 类型定义：`kt_xxx_t`（如 `kt_int8_t`）
- 宏定义：`KT_XXX`（如 `KT_OK`）
- 函数：`kt_xxx_yyy()`（如 `kt_led_on()`）
- 结构体：`kt_xxx_t`（如 `kt_button_t`）
- 枚举：`kt_xxx_t`（如 `kt_button_event_t`）

## 6. 扩展性考虑

### 6.1 添加新的平台支持

1. 在 `kt_port/` 下创建新的平台目录
2. 实现 `kt_port_gpio_xxx.c`, `kt_port_uart_xxx.c`, `kt_port_time_xxx.c`
3. 在 `kt_port.h` 中添加条件编译

### 6.2 添加新的组件

1. 在 `kt_components/` 下创建新的组件文件
2. 在 `kt_config.h` 中添加配置宏
3. 确保组件与现有模块解耦

### 6.3 添加新的驱动

1. 在 `kt_drivers/` 下创建新的驱动目录
2. 实现驱动的头文件和源文件
3. 通过 `kt_port` 接口访问硬件
4. 提供示例代码

## 7. 资源占用

ktlib 设计为轻量级库，资源占用尽可能少：

- **代码空间**：核心代码约 2-5KB（根据启用的功能）
- **数据空间**：每个驱动实例约 10-50 字节
- **栈空间**：函数调用栈深度浅，适合资源受限环境

## 8. 依赖关系

```
kt_drivers → kt_components → kt_port → kt_core
     ↓            ↓            ↓          ↓
  应用代码      通用算法      硬件操作    基础定义
```

- `kt_core` 无依赖
- `kt_port` 仅依赖 `kt_core`
- `kt_components` 依赖 `kt_core`
- `kt_drivers` 依赖 `kt_core` + `kt_port` + （可选）`kt_components`
